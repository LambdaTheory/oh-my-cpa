# 验收用例：左侧导航新增「能力」分组

依据：同目录 `prd.md`（定稿，唯一基准）；同目录评审页 `review-plain.html` 只作辅助阅读。用例只写「要的是什么」，预期写看得见、可检查的结果，不依赖实现计划与实现代码。

判定只有三种：**通过 / 范围内要修 / 范围外观察**。没跑过不写「通过」；一条路子打不开，如实写缺口，最多试三次，不算整体通过；被沙箱或审批拦住，不绕、不换工具硬开，升级给跟进或人。

## 0. 测试环境

### 0.1 被测两端与证据

| 记号 | 是什么 | 从哪来 |
|---|---|---|
| B（基线） | 拆页前：模型组在「运行」，仓库自有密钥面板在「密钥管理」页下半块，额度拆借建议页已上线但打开它时借用「OAuth 管理」的高亮 | 开发分支远端 `origin/dev` 的 `90a8d8ff`；在独立目录 `<BASE_DIR>` 用 `git worktree add --detach <BASE_DIR> 90a8d8ff` 取出，不动 H 所在目录 |
| H（PR 头） | 本需求实现合入后的分支头 | 提交号由验收报告写明；目录记作 `<HEAD_DIR>` |

- 凡写「与 B 相同」的预期，B 与 H 用**同一份数据、同一组步骤、同一语言与视口**各跑一遍再对照；B 上读不到的现象不凭印象判。
- 红项归因：任何失败先在 B 以同条件复现，B 同样失败的归「既有失败」，不算本需求引入。本机并行跑多个浏览器或服务时偶发的套接字缓冲耗尽（`ERR_NO_BUFFER_SPACE`、`bind … buffer space`）以单跑复现为准，不用加等待掩盖。
- 证据：报告写 `acceptance/report-r<N>.md`；截图放 `acceptance/shots/`，网络日志与对照 JSON 放 `acceptance/net/`，两处都不进 git。
- 只用假数据：不连生产、不用真实账号、不碰真实 agent 家目录；仓库名一律 `example/...`，密钥与令牌只用本环境生成的。

### 0.2 端口与目录变量

用例里一律写变量，不写具体端口。同机的审查、集成测试等小队会同时各起一套环境，各用各的段，所以每次开工先自选一段空闲端口再起环境。

| 变量 | 含义 |
|---|---|
| `<APP_PORT>`、`<CPA_PORT>`、`<CONTROL_PORT>` | H 的自托管应用、假 CPA、体验环境控制口 |
| `<BASE_APP_PORT>`、`<BASE_CPA_PORT>`、`<BASE_CONTROL_PORT>` | B 的同三项 |
| `<DEMO_PORT>`、`<BASE_DEMO_PORT>` | H、B 的演示模式应用 |
| `<PROBE_PORT>` | 浏览器场景整目录跑时的开发服务器（`pnpm verify:probes --port`） |
| `<HEAD_DIR>`、`<BASE_DIR>` | H、B 的工作区目录 |
| `<DATA_DIR>`、`<BASE_DATA_DIR>` | H、B 的应用数据目录 |
| `<BIN>`、`<BASE_BIN>` | H、B 构建出的二进制 |

起任何东西之前，先确认要用的端口空闲（输出为空才算空闲；把尖括号换成实际端口）：

```powershell
Get-NetTCPConnection -State Listen -ErrorAction SilentlyContinue |
  Where-Object { $_.LocalPort -in @(<APP_PORT>, <CPA_PORT>, <CONTROL_PORT>) }
```

规则：不沿用别的需求环境占着的端口。`pnpm check:ui` 的开发服务器端口固定写在脚本里（现为 5181），不能改，被占用时它直接失败而不是换端口；此时改用 `pnpm verify:probes --port <PROBE_PORT>` 跑整目录，或等占用方跑完。

### 0.3 自托管环境（H、B 同法）

体验环境脚本 `lending-experience-env.mjs`（在 `scripts/acceptance/` 下；开发分支已有，B 与 H 都带它）把假 CPA 与构建出的二进制一起拉起，登录、关闭额度自动刷新（避免后台轮次污染断言）、读一次额度。场景里有两张 Codex 卡（`codex-demo-a`、`codex-demo-b`）和一把客户端密钥。假 CPA 默认还登记了一个带页面的插件 `fixture-logger`，会让侧栏「插件」组多出一项，而 PRD 的条目计数按没有插件自带页写，所以第 6 步要先把它停用。两端都用这个脚本，保证环境一致。

1. 依赖与构建（在对应目录里；前端构建产物会嵌进二进制，必须先构建前端再编译）：

```powershell
pnpm install --frozen-lockfile
pnpm build
New-Item -ItemType Directory -Force "<DIR>/tmp" | Out-Null
# 本机没有 go 时用容器交叉编译 Windows 二进制：源码只读，输出目录可写，离线，复用已有的模块与构建缓存卷
docker run --rm --network none -v "<DIR>:/src:ro" -v "<DIR>/tmp:/out" `
  -v omc-go-mod:/go/pkg/mod -v omc-gocache:/root/.cache/go-build -w /src `
  -e GOPROXY=off -e GOFLAGS=-mod=readonly -e CGO_ENABLED=0 -e GOOS=windows -e GOARCH=amd64 `
  golang:1.27.1 go build -trimpath -o /out/omc-nav.exe ./cmd/oh-my-cpa
```

   `<DIR>` 取 `<HEAD_DIR>` 或 `<BASE_DIR>`，产物 `<DIR>/tmp/omc-nav.exe` 即 `<BIN>` 或 `<BASE_BIN>`。工作区的 `.git` 是指向主仓库的文件，若 go 报 VCS 状态错误，在 `go build` 后加 `-buildvcs=false`。首次编译失败按「最多试三次」处理，仍不通就记缺口。

2. 起环境（H 用 `<APP_PORT>` 一组，B 把变量换成 `<BASE_…>` 一组）。**三个端口变量都必须显式设置，`--check` 模式也一样**，否则脚本会落到它内置的默认端口，与同机其他小队冲突：

```powershell
$env:OMCPA_BROWSER_BINARY = "<BIN>"
$env:OMC_LENDING_APP_PORT = "<APP_PORT>"
$env:OMC_LENDING_CPA_PORT = "<CPA_PORT>"
$env:OMC_LENDING_CONTROL_PORT = "<CONTROL_PORT>"
$env:OMC_LENDING_DATA_DIR = "<DATA_DIR>"
node scripts/acceptance/lending-experience-env.mjs
```

   看到 `lending experience environment ready` 即可。应用基础路径是 `/omc`，下文写作 `<APP>` = `http://127.0.0.1:<APP_PORT>/omc`；B 的对应写作 `<BASE_APP>`。脚本进程不退出；停环境就是停这个进程，应用随之停止。
3. 登录：浏览器打开 `<APP>/`，密码是假 CPA 的管理密钥 `omc-e2e-management-key`（测试夹具常量，不是真实密钥）。接口调用先登录取会话，见 0.4。
4. 默认外观：中文、浅色。需要别的语言或主题时按 0.6 的 R10 设置，设置后刷新页面。
5. 脚本固定应用的主密钥，所以 B 种好数据后停掉，把 `<BASE_DATA_DIR>` 整个复制成 `<DATA_DIR>`，再用 H 的二进制起环境，两端就带着**同一份数据**；复制前必须先停应用，避免数据库写前日志没落盘。
6. 去掉插件自带页：每次起好环境并登录后，按 0.4 末尾的命令停用 `fixture-logger`，刷新页面，确认「插件」组只剩插件管理、插件商店两项。插件的启停状态在假 CPA 的内存里，重起环境后要再做一次；之后各用例里「没有插件自带页」的前提才成立。演示模式的数据集里插件都没有页面，不需要这一步。

### 0.4 接口前置：登录、偏好写入与隐藏设置集

```powershell
$APP = "http://127.0.0.1:<APP_PORT>/omc"      # B 换成 <BASE_APP_PORT>
Invoke-RestMethod -Method Post -Uri "$APP/api/auth/login" -ContentType 'application/json' `
  -Body '{"password":"omc-e2e-management-key"}' -SessionVariable s | Out-Null
# 写隐藏设置：值就是「被隐藏的页面地址」数组；写完刷新浏览器页面才生效
Invoke-RestMethod -Method Put -Uri "$APP/api/v1/preferences/omc_nav_hidden" -WebSession $s `
  -ContentType 'application/json' -Body '["/model-groups","/api-keys"]' | Out-Null
# 读回
(Invoke-RestMethod -Uri "$APP/api/v1/preferences" -WebSession $s).preferences.omc_nav_hidden
# 停用带页面的假插件，让「插件」组只剩插件管理与插件商店两项（0.3 第 6 步；重起环境后要再做一次）
Invoke-RestMethod -Method Patch -Uri "$APP/api/v1/management/plugins/fixture-logger/enabled" -WebSession $s `
  -ContentType 'application/json' -Body '{"enabled":false}' | Out-Null
```

`$s` 与浏览器是两个会话：浏览器里要单独登录（脚本里用 `context.request.post` 登录，会话落进浏览器上下文）。隐藏设置存在**部署的偏好**里，不是浏览器本地存储，换浏览器、换会话都读得到，所以造前置只能走偏好接口或设置面板，不能改浏览器本地存储。下表是用例引用的设置集；B 上没有 `/repo-keys`、`/quota-lending` 两个条目，B 的写法只保留 B 上存在的地址。

| 设置集 | 值 | 用在 |
|---|---|---|
| S0 | `[]` | 一个都不隐藏 |
| S1 | `["/model-groups","/api-keys"]` | 改动前已隐藏模型组与密钥管理 |
| S2 | `["/agent","/insights","/model-square"]` | 与搬家无关的几项 |
| S3 | `["/oauth-management","/omc-settings","/agent"]` | 手工写入含锁定项 |
| S4 | `["/model-groups","/repo-keys","/quota-lending"]` | 整个「能力」分组（B 写法：`["/model-groups"]`） |
| S5 | `["/model-groups","/repo-keys"]` | 「能力」留一项（B 写法：`["/model-groups"]`） |
| S6 | `["/api-keys"]` | 只隐藏密钥管理 |
| S7 | `["/insights","/usage/events","/pricing","/logs","/audit"]` | 整个「观测」分组 |

### 0.5 演示模式

演示模式是同一个二进制加演示开关：没有登录，不读网关，读接口放行，写接口被拒或只做不落盘的模拟。侧栏没有操练场（演示下该入口连同设置面板里的开关一并去掉）。`<DEMO_DATA_DIR>` 用一个新建的空目录（B 用 `<BASE_DEMO_DATA_DIR>`）：

```powershell
# 先清掉本机已有的 OMCPA_* 变量，再设下面这些；OMCPA_ENV_FILE 指向空设备，避免读到本机运营环境文件
Get-ChildItem Env: | Where-Object Name -like 'OMCPA_*' | ForEach-Object { Remove-Item "Env:$($_.Name)" }
$env:OMCPA_ENV_FILE = '\\.\nul'
$env:OMCPA_DEMO_MODE = 'true'
$env:OMCPA_BASE_PATH = '/'
$env:OMCPA_LISTEN_ADDR = '127.0.0.1:<DEMO_PORT>'
$env:OMCPA_DATA_DIR = '<DEMO_DATA_DIR>'
$env:OMCPA_MASTER_KEY = 'demo-nav-acceptance-master-key-000000'
$env:OMCPA_CPA_BASE_URL = 'http://127.0.0.1:1'     # 演示不读网关，故意给一个连不上的地址
$env:OMCPA_CPA_MANAGEMENT_KEY = 'unused-in-demo'
& "<BIN>"
```

等 `http://127.0.0.1:<DEMO_PORT>/api/healthz` 有回应后用，下文 `<DEMO>` = `http://127.0.0.1:<DEMO_PORT>`（基础路径是根，页面地址没有 `/omc` 前缀）。演示数据里仓库密钥一块现状是空的：公共演示数据集（`deploy/cloudflare/data/responses.json`，由同一份演示夹具生成）里 `repo-keys` 为 0 把密钥、0 待审批、0 待交付，`repo-key-audit-push` 为未启用；二进制演示的实际内容以实测为准，且 B 与 H 同读。

### 0.7 夹具与种子

**模型组种子（MG）**：自托管环境的「模型组」页有五个默认组（力工组、前端组、编排组、审查组、跟进组）；列表为空时点「恢复默认组」。取「力工组」：点「打开」进入详情（地址 `<APP>/model-groups/<GROUP_ID>`，记下 `<GROUP_ID>`），点「加入模型」进入添加页（`<APP>/model-groups/<GROUP_ID>/add`），勾 2 个模型，点「加入 2 个模型」，回到详情应见 2 个成员。AC-12、AC-13、AC-25 用它。

**仓库自有密钥夹具 DS-RK（桩数据层）**：同一份记录同时喂给 B 的密钥管理页下半块和 H 的新页，两端拿到的数据完全相同。写一个 Playwright 脚本，用请求拦截按下表应答读接口、拦下写接口（记录请求体后返回成功，不真写）；读接口的路径与字段形状照基线接口，见 `web/src/types/repoKeys.ts` 的类型与 `web/tests/repo-keys-cost.component.test.tsx` 里现成的夹具写法。

**仓库自有密钥真实层种子 RS**：在自托管环境里走真实接口造数，B 种好后按 0.3 第 5 步复制数据目录给 H。接口前缀 `$APP/api/v1/management/repo-keys`，带 0.4 的会话。

1. 造接收方公钥：用构建出的二进制在隔离的家目录里跑 `key gen`，标准输出只有一行 `x25519:…` 公钥：`$env:OMC_HOME="<临时目录>"; & "<BIN>" key gen --repo example/alpha`。
2. 控制台代提交申请：`POST …/applications`，体 `{"repo":"example/alpha","purpose":"验收造数","agent":"agent-a","public_key":"<上一步那一行>"}`。应答带申请编号、状态（`pending`；接收方已在名单里则直接 `approved`）以及只出现一次的审批链接。
3. 批准：`POST …/applications/<申请编号>/approve`，体 `{"reason":"验收造数"}`。批准后出现生效密钥，同时进入待交付。
4. 控制台代取密文，让这一条离开待交付：`POST …/applications/<申请编号>/ciphertext`。
5. 停用：`POST …/<密钥编号>/stop`，体 `{"category":"leaked","reason":"验收造数"}`；类别取值 `rotate`、`misuse`、`leaked`、`other`；密钥编号取自 `GET …/repo-keys` 的 `keys[].id`。
6. 申请重新启用：`POST …/<密钥编号>/reenable-request`，体 `{"reason":"验收造数"}`，产生一条重新启用类的待审批。

目标状态（各至少一条）：待审批 2（其中 1 条重新启用）、待交付 1、生效中 2、已停用 3（轮换、滥用、泄露各 1）。真实环境造不出的：非零用量（没有经这些密钥的真实请求）、审计平台推送（没有审计平台），这两项只在 DS-RK 层对照。若假 CPA 完不成批准（接口报错），试满三次后记缺口，相关 F 项只在桩层对照，不算真实环境通过。

### 2.1 AC-10 的对照方法

被测两端：**B** 是 `<BASE_APP>/api-keys` 页面下半块的面板整体，**H** 是 `<APP>/repo-keys` 整页。两端吃同一份数据：桩层用同一个脚本喂 DS-RK（0.7），真实层用复制出来的同一份数据目录（0.3 第 5 步）。步骤、语言、视口也两端一样。

每个观察点记四类东西，B 与 H 逐项比，必须相同：

1. **可见文字**：面板或页内容区的全部可见文字，按行取出，去掉多余空白后逐行比。
2. **可操作控件**：每个按钮、链接、输入框、筛选器的「角色、可访问名称、是否禁用、悬停提示」。
3. **请求**：每个操作发出的请求，记「方法、路径（编号换成占位）、查询参数名与值、请求体字段」。
4. **结果状态**：操作后界面的状态，含提示、行数、计数、弹窗内容。

**唯一允许不同的是页面外壳**：B 里面板嵌在密钥管理页中；H 里是独立页，多出页头标题「仓库自有密钥」、统一页头自带的刷新、面包屑与标签页标题。外壳以外，H 多出一项、少一项或结果不同，都是差异：多出算「多了」，缺失算「少了」，两者都按范围内要修登记。
