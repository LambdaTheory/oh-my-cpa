# 需求要点：跨凭证额度拆借（显示层与建议层）

## 1. 需求原话整理

两台 Codex Pro 200 凭证的周限额不同步：A 还剩 88%，11/27 才自然重置；B 只剩 40%，11/25 就自然重置。想要的用法是这两天优先用 A、少用 B，让 B 的 40% 撑到 11/25 回满；B 回满后再反过来偏用 B、把 A 养到 11/27。本质是按「谁快自然重置就少用、把额度留给还没到期的」排优先级，不是平均分，也不是只看剩余百分比高低。

## 2. 已确认事实（来自调研报告与控制台只读核对）

- 每张凭证的每个额度窗口都有剩余百分比、重置时刻、重置文字标签和重置精度（精确 / 推算 / 近似）；部分插件只给文字、没有具体时刻。
- Codex 的重置时刻可能来自「距现在多少秒」的推算值；Claude 解析失败时会退化为无时刻。精度必须被展示，不能当成精确值。
- 控制台一张凭证一条额度记录，带 provider、凭证类型与套餐（plan_type / plan_label），但没有「同池 / 同账号池」分组，也没有跨卡比较。
- 现有单卡建议（reset_advice）只回答「重置权益（Codex 重置次数 / Claude 重置授权）要不要在到期前用掉」，只覆盖 codex / claude，要求 2 小时内的权益读数，不跨卡比较。
- 预测侧已逐窗口给出「能否撑到重置」「数据年龄」等读数，但不按卡排优先级。
- priority / weight 是 CPA 的调度字段：高 priority 先被选中，weight 只在加权轮询且同优先级内生效，会话亲和可能绕过；改它会影响线上所有请求。项目边界是「不做自动路由，不进 CPA 请求路径」。

## 3. 用户与场景

| 角色 | 场景 | 关心什么 |
|---|---|---|
| 运营人员 | 早上打开凭证列表，决定今天哪张卡多承接流量 | 每张卡离自然重置还有多久；同套餐里先偏用谁、少用谁；理由是否可信 |
| 值班人员 | 某张卡余量快速下降，临时调整用法 | 快重置的卡还剩多少、是否会在回满前耗尽；建议的有效期到什么时候 |
| 负责额度成本的人 | 看跨卡建议是否值得照着做 | 建议依据的读数时间、重置精度、数据不全时会不会乱给 |

## 4. 范围

**做**：

- 显示层：列表行里强化「距自然重置还有多久」，新增「快重置 · 余量高/低」标记，新增按距自然重置排序。
- 建议层：同 provider + 同套餐的凭证组成可拆借同池，给出「偏用谁、少用谁、为什么、有效期到哪」的只读建议；数据不全时明确「无法建议」。
- 明确建议层与现有单卡重置权益建议的分工和展示位置。

**不做**：

- 不写 CPA 路由字段，不做自动路由、自动切凭证、自动停用（是否落路由权重单列待确认）。
- 不改现有单卡重置权益建议的语义、阈值和展示位置。
- 不消耗重置次数 / 重置授权，不新增上游采集，不新增通知。
- 不覆盖 5 小时、滚动、模型级、分组级窗口的建议；这些窗口只在单卡行里照常展示。

## 5. 关键产品口径（PRD 按此展开，评审页可改）

| 口径 | 取值 | 理由 |
|---|---|---|
| 可拆借同池 | 同 provider + 同 plan_type | 调研里唯一现成的可比键；套餐不同则模型访问和额度规模不同，不能互相替代 |
| 池内比较窗口 | 标准窗口（凭证自己的额度）且周期 ≥ 24 小时 | 5 小时窗口自愈太快，用它排优先级会来回跳；模型/分组窗口口径不同 |
| 单卡的建议窗口 | 该卡所有长窗口中剩余百分比最低的那个 | 它是最先卡住这张卡的窗口 |
| 比较量 | 重置前日均可用 = 剩余百分比 ÷ 距自然重置天数（不足 1 小时按 1 小时算） | 把重置时间放进分母，避免只看剩余高低；同时保证每张卡都能撑到自己的重置 |
| 分先后门槛 | 最高与最低相差 ≥ 1 个百分点/天 | 读数精度和推算重置的误差在 1 个百分点/天以内，避免把噪声说成建议 |
| 快重置 | 距重置 ≤ 窗口周期的 1/3 | 周窗口约 56 小时、日窗口约 8 小时、5 小时窗口约 1.7 小时，跨窗口类型可复用 |
| 余量高低 | 剩余 ≥ 50% 为高，< 50% 为低 | 与现有余额配色分档解耦，只回答「快重置时该不该省」 |
| 读数有效 | 沿用现有额度鲜度界：至少 2 小时、长窗口按周期的 1/4、最多 24 小时 | 与预测和单卡建议的现有口径一致，不另造一套 |

## 6. 待确认（评审页上点选）

- q01：是否把建议落成 CPA 路由权重（priority / weight）。推荐「只做提示、不动路由」。
- q02：建议窗口是否只覆盖周期 ≥ 24 小时的标准窗口。推荐「只覆盖长窗口」。
- q03：同池偏用顺序按「重置前日均可用」还是按「重置时刻从晚到早」。推荐「重置前日均可用」。
- q04：快重置标记是否按窗口周期的 1/3 判定、余量以 50% 分高低。推荐「按此规则」。

## 7. 成功标准

- 运营人员不打开凭证详情，就能在列表页看到某张卡「还剩多少、离自然重置多久、是否快重置」。
- 两张以上同套餐凭证存在时，列表页给出可执行的偏用/少用建议，并写明依据的读数时间、有效期和每张卡的数字。
- 缺重置时刻、读数过期、窗口口径不同时，建议明确显示「无法建议」及原因，不猜测、不退回只按剩余百分比排序。
- 建议只读：页面上没有任何写入 CPA 路由、消耗重置权益的动作。
